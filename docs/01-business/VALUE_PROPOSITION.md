## 4. Why Problem-First Matters

The software industry has an inverted development culture:
* Agencies ask: *"What features do you want to build?"*
* Freelancers ask: *"What tech stack do you want us to use?"*
* Platforms ask: *"Which of our templates do you want to rent?"*

All of these questions skip the most important step: **understanding the problem**.

When engineering begins with technology rather than the problem, the result is predictable: feature bloat, misdirected capital, and software that sits unused while employees revert to spreadsheets.

At `[STUDIO_NAME]`, we start with the problem because:
1. **The right problem defines the simplest solution**: A substantial portion of requested features turn out to be unnecessary once the true root bottleneck is identified.
2. **Lean software is durable software**: Building only what matters minimizes surface area for bugs, reduces maintenance costs, and maximizes operational velocity.
3. **Outcomes trump code volume**: Software is an investment, not a decoration. Its sole justification is moving a business metric.
